# Tasks: Marketing, Legal and SEO Pages

**Input**: Design documents from `/specs/005-marketing-pages/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/routes.md, quickstart.md; features 001 and 002 shipped on this branch (accounts, personas, categories, media, brief builder, creators, preview route).

**Design**: every task that changes visible UI follows the `ui-design` skill and the `impeccable` workflow (context → craft floor → build → detector); each public surface closes with the impeccable finish review (`ship`) and DESIGN.md (Principle IX). The world is "The Brief Bar" (`PRODUCT.md`, `.impeccable/surfaces/`); T004 records the five surface briefs before any UI is built. No invented counts, ratings, testimonials or logos anywhere, seed content included.

**Tests**: REQUIRED by the constitution (Principle III). Every phase lists its tests first; write them, watch them fail, then implement. Name tests with the 005 ids (`MP-US1-S4`, `MP-FR-003`) — `quickstart.md` holds the scenario → test mapping and `pnpm check:scenarios` enforces it.

**Organization**: Phases 1–2 build shared infrastructure; Phases 3–7 are one user story each (US1 pages, US2 legal, US3 guides, US4 intent pages, US5 not-found/removed), each independently testable once Phase 2 is done; Phase 8 is cross-cutting polish. Each story ships its own migration (`marketing_pages_pages`, `…_legal`, `…_guides`), which amends plan.md's "one migration" to three small ones so a story can ship alone.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: US1 pages · US2 legal · US3 guides · US4 intent pages · US5 not-found/removed
- File paths are relative to the repository root; `apps/web/src` is abbreviated as `web/` below; integration tests use the harness in `apps/web/tests/integration/setup`
- Every Bash call needs Node 24 (`nvm use`); integration tests need Docker

## Path Conventions

- `apps/web` — Next.js 16 + Payload 3 app (`web/app`, `web/modules/{pages,legal,guides}`, `web/shared`, `apps/web/tests`)
- `packages/domain/src/pages` — framework-free rules, 100 % covered
- No new package is added by this feature (plan.md Complexity Tracking)
