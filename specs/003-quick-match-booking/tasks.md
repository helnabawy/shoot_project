# Tasks: Quick Match Matching, Quotation and Booking

**Input**: Design documents from `/specs/003-quick-match-booking/`

**Prerequisites**: plan.md, spec.md (clarified 2026-11-07), research.md, data-model.md, contracts/, quickstart.md; features 001 (briefs, accounts, option sets, site settings) and 002 (creator profiles, listings, cached summaries) shipped on this branch.

**Design**: every task that changes visible UI follows the `ui-design` skill and the `impeccable` workflow (context → craft floor → build → detector); each surface closes with the impeccable finish review (`ship`) and DESIGN.md (Principle IX). The world is "The Brief Bar". One primary action per screen, WhatsApp always secondary, no invented ratings, counts or testimonials.

**Tests**: REQUIRED (Principle III). Every phase lists its tests first; write them, watch them fail, then implement. Name tests with the 003 ids (`QM-US2-S3`, `QM-FR-009`) — see the mapping in `quickstart.md`.

**Organization**: Phases 1–2 build shared infrastructure (price rules, domain rules, schema, migration, seed); Phases 3–6 are one user story each (US1 match, US2 quotation, US3 lifecycle, US4 admin), in delivery order; Phase 7 is cross-cutting polish.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: US1 see who's free · US2 details and quotation · US3 creator confirms, payment, delivery · US4 admin oversight
- Paths are relative to the repository root; `apps/web/src` is abbreviated as `web/`; integration tests use the harness in `apps/web/tests/integration/setup`

## Path Conventions

- `apps/web` — Next.js 16 + Payload 3 app (`web/app`, `web/modules/pricing`, `web/modules/booking`)
- `packages/domain/src/pricing`, `packages/domain/src/booking` — framework-free rules, 100 % covered
- No new package (plan.md Complexity Tracking)
